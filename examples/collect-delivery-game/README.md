# Collect and deliver

This independent example is a statically linked user game. Open `scenes/collect-delivery.project.json` with `collect-delivery-editor`. In the editor, start Play, take control, then use the registered `move` intent with `{"dx":1,"dy":0}` (or another direction) and `act` with `{"press":1}`. In the native player, one arrow-key press moves one tile on each nonzero axis and Space acts. Horizontal and vertical movement together form a diagonal step. A movement direction takes precedence if held with Space, so it cannot also collect or deliver. Raw input with primary action and movement axes together is rejected. Release to arm another movement/action. Pick up the item before acting at the destination. The red hazard loses the run. After a win or loss, release Space and press it again to restart.

The editor uses the engine's registered-project, scene save/reopen, Play and command-input paths. `collect-delivery-player` is the concrete native runtime. Its optional bounded `--trace TRACE.json --scene SCENE.yaml` mode is a headless CPU oracle for deterministic testing; it is not a substitute for testing the native window or GPU presentation.

On Linux x86-64, build the player and bundle tool with the same `ORR_STATIC_STANDALONE_BUILD_SHA` set to the exact source commit. Then run `collect-delivery-bundle --runtime PLAYER --runtime-sha256 SHA256 --scene AUTHORED_SCENE --output NEW_DIRECTORY --source-sha COMMIT_SHA --trusted-runtime`. `--trusted-runtime` is required to assert that the supplied executable is the intended user-game build. The exported bundle contains the runtime and admitted scene, not this project source. The runtime also supports the starter's normal `--identity`, `--provenance`, replay, record and observe options.
