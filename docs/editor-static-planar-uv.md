# Create planar UVs for a static prop

In the model import panel, choose a cooked static source, inspect it, enable **Static planar UV**, and explicitly choose one used material. Select `xy`, `xz` or `yz`, enter the model-space origin and positive units per texture repeat, then choose a new `.planar-uv.json` asset identity. Acknowledge the license and import to a new package destination. Install the result, preview it in the package browser and assign it as a static Room prop; Undo/Redo, Save and reopening use the normal model-binding flow.

Projection uses each primitive's transformed model-space vertex position, before any scene entity placement. The ordered plane axes become U and V: `xy` uses X/Y, `xz` X/Z and `yz` Y/Z. Subtract the corresponding origin and divide by the respective units per repeat. Only UV0 on primitives using the selected material changes. This does not unwrap surfaces, create seams or generate colliders; faces parallel to the projection direction may overlap. Texture repetition still follows the material's existing sampler settings.

The panel validates finite input values before binary32 conversion and rejects positive units that narrow to zero or values that overflow. The existing offline recipe and producer use binary32 origin/units; the entered admitted numbers are retained in the recipe bytes. Invalid output UVs, unsupported source data and stale inspections fail before package publication. Editing any source/context/specification requires current inspection and explicit consent; variants are mutually exclusive.

The output is an immutable cooked static `model.orrmodel` package with models-only capability. Positions, normals, primitive transforms, indices, materials, images and unselected UVs are preserved. Source bytes remain untouched. New identity/provenance binds the exact generated recipe and captured direct source hash; historical dependency paths are not reread. Publication uses the existing license, source-hash and new-destination checks.

Focused acceptance covers all three planes with transformed primitives and independent UV expectations, selected/unused materials, numeric boundaries, source/provenance preservation, stale work, package installation and editor assignment/history/Save/reopen/Room CPU use. Linux CPU tests and strict feature checks do not verify Windows execution, physical GPU/window rendering, native game export or actual play/video.
