# Import an authored animation model into a Room

A `package-manager,room-animated-models` editor can import a saved native `.animated.json` model into a new content package. This connects existing animation authoring output to installed-package preview and model bindings without requiring manual package metadata. It does not import an animation recipe or resolve source dependencies.

Open a saved local Room and **Content packages**. In model import, choose **Cooked animated model**, select the saved model and a nonempty UTF-8 license file, enter an absent package directory/name/version, and explicitly acknowledge distribution rights. Start the import. The resulting package contains `model.animated.json`, `LICENSE.txt` and `orr.package.json`, with `models` and `animation` capabilities. The existing strict animated-model decoder must accept the self-contained payload and at least one animation clip. The model bytes are copied unchanged. Dependency digests remain provenance, not files to fetch or execute.

Import does not install or assign. Preview and explicitly add the generated package, verify installed content, then use the animated asset for the selected compatible entity and save model bindings. Reopen the complete project to confirm the installed binding. An existing Room character policy can select the imported model's matching clips; import itself does not change character mappings. Build consumers and exports with explicit animated-model/character support as appropriate, and preserve the existing project lighting consent.

The importer requires Animated model mode and compiled Room animated support before any cooked-animated source or destination access. The UI clears rights acknowledgement when changing formats and does not silently reselect results from a prior project/source. The license is supplied metadata, not a legal determination. Inputs remain bounded regular files; existing path/changed-input and no-replace publication checks apply. Existing destination data is preserved, failures are not silently retried and an uncertain worker outcome does not establish absence. Static GLB and cooked-static routes retain their existing contract.

Focused acceptance separates codec/feature/kind/path failures, payload and license preservation, actual import widgets, explicit package installation/assignment/saved binding, and source-hidden exported headless gameplay. The latter checks the actual saved imported package, CPU poses and simulation checksum. These checks do not establish native-window input, GPU pixels, audio-device behavior or Windows positive publication. Known Windows publisher access failures are preserved without retry, and a locked computer is not unlocked or bypassed.
