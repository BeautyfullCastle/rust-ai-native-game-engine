# Mission-Preserving Mesh Geometry

The `mesh-mission` editor profile can stage a mesh geometry edit while an active mission is configured. This path is explicit: enable **Preserve and reproject the active mesh mission**, stage geometry, review the projection preview, confirm, and choose **Apply geometry and reproject mission**. Ordinary **Place mesh agent** remains blocked while a mission is active; geometry is never silently rebound.

The preview lists the old and projected agent start/goal, every active collectible, the exit, and both graph revisions. The candidate uses the currently authored nonnegative vertical tolerance, preserves distance-per-tick, mission count, and each objective radius, and is rejected while mission progress is nonzero. It also verifies a bounded navigation path from the projected agent start to the goal, every active collectible, and the exit; points on disconnected walkable islands are rejected even if they individually project onto the graph. The host independently checks the expected current checksum and old graph revision, validates the complete reflected candidate pin, reprojects the enabled mission, and commits the new pin and mission in one host history entry. Projection, route, admission, stale-context, or host failures leave the existing host document unchanged. Canceling the preview keeps the staged local geometry/history available and does not call the host.

This workflow is limited to a local MeshNavigation scene in Edit mode with a staged graph derived from its currently admitted graph. Existing art, props, camera, lighting, HUD, and animation sidecar blockers remain in force; those graph-bound records must be removed or saved elsewhere before the edit. Mission progress must be zero before reprojection; pending agent start, goal, and speed edits must also be applied or discarded. The currently authored nonnegative vertical tolerance is the only route setting this workflow may change. It does not enable geometry replacement through **Place mesh agent**, open remote/viewer mutation, or weaken the normal workspace and presentation guards.

The operation requires the matching `mesh-mission` game/host feature profile and the host's `mesh.geometry.reproject` SceneEdit method. It uses the existing scene schema and mission singleton; it adds no sidecar, persisted schema field, dependency, or alternate game ABI.
