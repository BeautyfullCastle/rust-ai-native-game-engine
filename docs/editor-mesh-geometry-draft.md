# Staged mesh geometry workflow

The optional `mesh-navigation` editor workflow can preview walkable geometry before committing it. Staged quad and vertex edits are displayed as a surface-only preview in the production viewport; the preview contains no entity, GUID, agent, or route and does not mutate the host Frame. While it is pending, the preview replaces the visible agent/route and bound art or props, but those host-backed values remain unchanged.

Use `Undo staged geometry` and `Redo staged geometry` for the bounded local draft history. These controls are separate from ERP Undo/Redo: only `Place mesh agent` validates the graph and commits it with the agent specification as one ERP history entry. `Discard unplaced changes` explicitly clears the draft. Saving, opening another scene, Play, and export remain blocked until the draft is placed or discarded. `Frame staged geometry` adjusts the view to the draft bounds and is not part of geometry history.

The preview colors admitted walkable triangles blue and faces rejected by the agent slope profile orange. Local history retains at most 16 canonical graph states, each limited to 8 KiB of serialized graph data. This bounds retained serialized history; it is not a process-memory cap. Camera framing is outside the geometry history.

Geometry forms use canonical vertex and face indices. Removing faces may leave unreferenced vertices in the graph array; these vertices are serialized but do not define walkable triangles. Invalid indices, degenerate faces, disconnected routes, and rejected submissions preserve the last valid draft and host scene. Geometry editing is intended for a new or clean mesh authoring state: existing graph-bound art, props, camera, or animation sidecars must be explicitly removed and saved before changing graph revision.

The authored graph is embedded in the saved mesh scene and can be reopened in a fresh Physics editor session. Walkable triangles are navigation data only; this workflow does not create colliders, physical ramps, or a physics controller. Optional mesh-game export is a bare three-file bundle (scene, player executable, manifest); this acceptance does not claim native runtime execution or external model-package handling. Hardware Vulkan GPU acceptance uses the actual editor viewport and does not synthesize physical operating-system input.

The ignored Windows x64 acceptance test is `mesh_geometry_draft_ui::ui_previews_staged_geometry_with_local_history_then_commits`. It requires `ORR_MESH_DRAFT_ACCEPTANCE=1`, `ORR_REQUIRE_GPU=1`, `WGPU_BACKEND=vulkan`, and a fresh absolute `ORR_MESH_DRAFT_CAPTURE_DIR`. `ORR_MESH_DRAFT_OUTPUT` may select a new scene file; optional bundle export requires both `ORR_MESH_DRAFT_EXPORT_OUTPUT` and `ORR_MESH_EXPORT_RUNTIME`.
