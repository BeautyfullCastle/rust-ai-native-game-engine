# orr_app: 저장 슬롯, 체크포인트, WAV 소리, 이벤트 소리

`orr_app`으로 만든 게임이 코드 몇 줄로 쓰는 기능입니다. 이슈 #107(저장/체크포인트와 오디오 만들기)의 일반 부분입니다. 한 게임에만 묶인 저장(Collect 최고 점수, Room 클리어 표시, Stormglass 런 저장)은 그대로 두었고, 여기서는 건드리지 않았습니다.

## 저장 슬롯

저장은 **검증된 프레임의 결정론 스냅숏**입니다(`Frame::to_bytes`: 틱, 모든 컴포넌트·싱글턴·리스트, 프레임 난수 상태, 프레임 체크섬). 거기에 작은 머리글(게임 ID와 버전, 플레이어 수, 틱 속도, 체크섬, 라벨, 시각)을 붙여 파일 하나에 씁니다. 불러오기는 **그 프레임에서 새 오프라인 세션을 시작**합니다. 새 세션의 체크섬은 저장한 체크섬과 같고, 같은 입력이면 저장하지 않은 게임과 같은 미래를 걷습니다(난수 상태도 프레임 안에 있습니다).

```rust
App::<StarPick>::new()
    .saves("star_pick", 1)                  // 게임 ID(폴더 이름)와 게임 버전
    .save_key(KeyCode::F5, "quick")         // 키로 저장
    .load_key(KeyCode::F9, "quick")         // 키로 불러오기
    .checkpoint_on("checkpoint", |e: &Mark| Some(format!("{}단계", e.level)))  // 확정 이벤트가 저장을 부른다
```

뷰 코드에서는 `ctx.save_game("슬롯", "라벨")`, `ctx.load_game("슬롯")`, `ctx.list_saves()`, `ctx.delete_save("슬롯")`, `ctx.save_notice()`를 씁니다. `save_notice()`는 마지막 저장·불러오기·체크포인트의 결과(`SaveNotice::Saved`, `Loaded`, `Failed`)를 2.5초 동안 줍니다. 말은 게임이 자기 언어로 정합니다. 폴더를 직접 정하려면 `.save_folder(경로)`(`.saves(..)` 다음에 부릅니다)입니다.

- **무엇을 저장하나.** `ctx.verified()`의 프레임입니다(오프라인에서는 예측과 같습니다). 체크포인트는 확정된(`Verified`) 이벤트에서 부르고, 그 순간의 가장 새 확정 프레임을 저장합니다. 게임이 체크포인트를 원하면 이벤트를 하나 내보내고 `.checkpoint_on`에 그 이름을 줍니다.
- **불러오기는 검사가 먼저입니다.** 파일을 끝까지 읽고 검사하고 프레임을 풀어서 체크섬까지 맞춘 뒤에야 "받아들인 불러오기"가 됩니다. 어느 하나라도 틀리면 오류를 돌려주고, 달리는 세션은 건드리지 않습니다. 받아들인 불러오기는 그 프레임이 끝날 때 실행됩니다: 새 `PlaySession`이 `InProc` 브리지를 갈아 끼우고, 씬 뷰는 `on_resync`와 `on_load`를 한 번씩 받고(`on_load`는 불러오기에만 옵니다. 화면을 저장한 상태에 맞출 때 쓰고, `Screens::resume()`이 타이틀·일시정지·결과 화면에서 새 라운드 `Restart` 없이 바로 플레이로 돌아갑니다), 이전 세션의 이벤트 기억과 이벤트 소리는 지워집니다. 선수 등록(`Added` 신호)은 다시 하지 않습니다. 프레임에 이미 있습니다.
- **오프라인만.** `--host`와 `--connect` 실행은 저장 슬롯이 없습니다(`SaveError::Unavailable`, 터미널에 한 번 알립니다). 네트워크 게임은 저장을 불러오지 않습니다. 서버의 상태를 한 창이 마음대로 되돌릴 수 없기 때문입니다.

### 폴더와 파일

| 시스템 | 폴더 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\orrery\games\<게임>\saves\` (`LOCALAPPDATA`가 없으면 `%USERPROFILE%\AppData\Local`) |
| Linux | `$XDG_DATA_HOME/orrery/games/<게임>/saves/`, 없으면 `~/.local/share/...` |
| macOS | `~/Library/Application Support/orrery/games/<게임>/saves/` |

환경 변수는 절대 경로일 때만 씁니다. 슬롯 하나가 파일 하나입니다: `slot-<이름>.orrsave`. 슬롯 이름은 영문자, 숫자, `-`, `_` 1~32자이고 게임 ID는 같은 문자 1~64자입니다(경로 문자나 `..`는 경로를 만들기 전에 거절합니다). 폴더는 첫 저장에서 만들고, `orrery/games/<게임>/saves`의 어느 한 칸이라도 링크나 재해석 지점이면 거절합니다. 읽을 때는 `orr_fsid::open_file`로 열어서 링크, 폴더, FIFO를 거절하고 64 MiB를 넘으면 읽지 않습니다.

**쓰기는 원자적입니다.** 같은 폴더에 임시 파일(`.slot-이름.orrsave.<프로세스>.<번호>.tmp`)을 `create_new`로 만들고, 다 쓰고 `sync_all`한 뒤 `rename`으로 슬롯 위에 덮어씁니다(Windows와 Unix 모두 기존 파일을 바꿉니다). 어느 단계에서든 실패하면 임시 파일을 지우고 이전 저장은 그대로입니다. 프로세스가 도중에 죽으면 `.tmp`가 남을 수 있지만 슬롯 목록은 `slot-*.orrsave`만 봅니다.

### 파일 형식 (버전 1)

작은 쪽부터(little endian), 길이는 `u32`입니다.

```text
"ORSV"  버전 u32 (= 1)
게임 ID(길이, utf-8)   게임 버전 u32   저장 시각 u64(1970년부터 초)   라벨(길이, utf-8, 120바이트까지)
플레이어 수 u8   틱 속도 u32   틱 u64   프레임 체크섬 u64   프레임 바이트(길이 u64, 바이트)
앞의 모든 바이트의 xxh3 u64
```

- **형식 버전은 하나(현재 1)입니다.** 개발 단계라서 옛 버전을 옮기는 코드는 없습니다. 다른 버전의 파일은 두 버전을 모두 말하는 메시지로 거절합니다(`SaveError::UnsupportedVersion`: "the save has format version 2, this build reads only version 1; saves are not migrated"). 형식을 바꾸면 `SAVE_VERSION`을 올립니다. 버전은 파일 해시보다 먼저 검사해서, 모르는 버전은 "깨졌다"가 아니라 "버전이 다르다"로 보입니다.
- **게임 ID가 다르면** `ForeignGame`, **게임 버전이 다르면** `GameVersion`(게임이 저장 데이터를 바꿨을 때 `.saves("id", 버전)`의 버전을 올립니다), **플레이어 수나 틱 속도가 다르면** `Mismatch`, 프레임의 컴포넌트 스키마가 이 게임과 다르면 `Corrupt`입니다(`Frame::from_bytes`가 스키마와 체크섬을 확인합니다).
- 프레임 바이트 안에도 프레임 체크섬이 있습니다. 파일 해시가 맞아도 프레임을 풀고 나서 그 체크섬이 머리글의 것과 같은지 다시 봅니다.

## WAV 소리

```rust
App::<StarPick>::new()
    .sound_file("pickup", "assets/pickup.wav")            // 실행이 시작될 때 읽는다 (상대 경로는 작업 폴더 기준)
    .sound_wav("pickup", include_bytes!("pickup.wav"))    // 또는 프로그램에 넣은 바이트
```

`orr_app::clip_from_wav(&[u8])`가 읽습니다. **16비트 정수 PCM과 32비트 실수**(`WAVE_FORMAT_EXTENSIBLE` 포함), **모노(양쪽에 같게)와 스테레오**, 8000~192000 Hz, 10초까지(`Clip`의 한계)입니다. 그 밖의 청크는 건너뜁니다. 8비트, 24비트, 3채널 이상, 압축 형식, 실수 샘플이 숫자가 아니거나 -1..1 밖인 파일, 자르다 만 파일, 잘못된 머리글은 이유를 말하며 거절합니다. 파일을 못 열거나 거절당하면 **실행이 오류로 멈추고** 소리 이름과 파일 이름을 말합니다.

**샘플 속도 바꾸기(리샘플)는 믹서가 합니다.** 클립은 파일의 속도를 그대로 갖고, 오디오 출력(Kira)이 재생할 때 출력 속도로 맞춥니다. 22050 Hz 1초짜리 파일은 44100 Hz 출력에서도 1초이고(테스트로 확인), 더 빠르게 들리지 않습니다. 기존 `orr_asset_cook`의 WAV 파서(`parse_wav`)는 48 kHz, 1초 이하의 16비트 PCM만 받는 패키지 요리용이라 쓰지 않았습니다.

## 소리 조절

`ctx.audio()`(`Audio`)에 더한 것:

| 호출 | 하는 일 |
| --- | --- |
| `play_named_with("이름", 음량, 반복)` | 등록한 소리를 음량(0~1, 선형 진폭)으로, 반복하며 켭니다 |
| `play_looped(&clip)` | 멈출 때까지 되풀이합니다 (`stop`이 끕니다. 반복 소리는 스스로 끝나지 않습니다) |
| `set_volume(손잡이, 음량)` | 재생 중인 소리의 음량을 20 ms에 걸쳐 바꿉니다. 이미 끝난 소리면 아무 일도 없습니다 |
| `set_master_volume(음량)`, `master_volume()` | 모든 소리의 음량입니다. 아직 열리지 않은 출력에도 열릴 때 적용됩니다 |
| `has_sound("이름")` | 그 이름의 소리가 등록되어 있는지 |

낮은 층에는 `Clip::volume(0~1)`, `Clip::looped()`, `EventAudio::set_volume(id, 음량)`이 있습니다(`orr_audio`). 범위 밖 값은 자르고 숫자가 아닌 값은 0으로 읽습니다. 자리(`Clip::at`)가 있는 소리는 거리에 따른 음량에 클립 음량이 더해집니다(듣는 이가 움직여도 유지됩니다).

## 이벤트 소리

```rust
App::<Burst>::new()
    .sound_wav("flash", FLASH_WAV)
    .on_event_sound(|e: &Flash| Some("flash"))   // 이벤트마다 소리 이름을 돌려준다. None이면 소리 없음
```

**소리를 켜고 끄는 일을 한 곳이 합니다.** 뷰에 소리 코드가 필요 없습니다.

| 이벤트 알림 | 소리 |
| --- | --- |
| `Predicted` | 켠다(손잡이를 기억한다) |
| `Verified`, 앞에 `Predicted`가 있었다 | 그대로 둔다. 두 번째 소리는 없다 |
| `Verified`, 앞에 알림이 없었다(오프라인) | 켠다 |
| `Canceled` | 그 이벤트의 소리를 끈다 |
| 같은 키의 되풀이 `Predicted`·`Verified` | 아무것도 하지 않는다 |
| `Canceled` 뒤의 `Verified`(늦은 알림) | 아무것도 하지 않는다 |
| `Canceled` 뒤의 `Predicted`(바뀐 이벤트) | 새로 켠다 |

이벤트 키(`EventKey`)당 최대 512개를 기억해서 롤백이 이벤트를 그대로 둘 때 소리가 되풀이되지 않습니다. 512개를 넘으면 소리가 없거나 이미 확정·취소된 키 중 가장 오래된 것부터 버립니다. 아직 확정을 기다리는 예측 소리의 키와 핸들은 남겨 두므로 뒤늦은 `Canceled`가 그 소리를 멈추고 `Verified`가 같은 소리를 다시 내지 않습니다. 512개가 모두 확정 대기 소리일 때만 가장 오래된 것을 버리고 그 소리를 멈춥니다. **`ViewResync`가 오면** 아직 확정되지 않은 소리를 끕니다(그 `Canceled`는 오지 않습니다). 그 키의 `Predicted` 기억은 지우므로, 같은 키의 `Verified`가 뒤늦게 오면 끊긴 소리 대신 처음부터 온전한 소리가 납니다. 확정된 소리는 건드리지 않습니다. **불러오기(세션 교체)는** 아직 재생 중인 이전 세션의 소리를 확정 여부와 상관없이 모두 끄고 기억을 모두 지웁니다(확정된 소리의 핸들은 소리가 끝날 때까지 들고 있습니다). 바인딩이 여러 개면 각각이 소리를 낼 수 있고, 이름이 등록되어 있지 않으면 건너뜁니다.

## #107 점검표에서

이 조각으로 된 것: 일반 저장 슬롯과 체크포인트(오프라인), WAV 소리 읽기, 소리 음량·반복 조절, 이벤트 소리 바인딩. 아직 안 된 것은 맨 아래 "남은 것"에 있습니다.

### 남은 것

- 네트워크(`--host`, `--connect`) 게임의 저장 불러오기는 의도적으로 없습니다.
- 저장 형식 마이그레이션은 개발 단계라서 없습니다(버전이 다르면 거절).
- 저장 슬롯 고르는 **화면(메뉴)**은 만들지 않았습니다. 목록과 삭제 API(`list_saves`, `delete_save`)만 있습니다.
- 자동 저장 주기, 프로세스 도중 사망 때 남은 `.tmp` 청소, 저장 파일 암호화·서명은 없습니다.
- 인벤토리·프리팹 재가져오기 같은 #107의 다른 항목, 믹서 버스·음악 버스, 공간 소리의 새 기능, 웹·모바일의 소리와 저장은 이 조각 밖입니다.
- 튜토리얼 3~5단계는 아직 코드로 만든 "딩"과 뷰 안의 소리 코드를 씁니다(2단계만 바꿨습니다).
- Windows 이외 시스템의 폴더 규칙과 Unix의 쓰기 실패 테스트는 이 컴퓨터(Windows)에서 실행하지 못했습니다.
