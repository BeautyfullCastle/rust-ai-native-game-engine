# Import a materialized sprite-gen atlas

The optional Linux `orr_pkg create-sprite --sprite-gen` route converts an existing
sprite-gen `manifest.json` plus an explicit PNG into a normal Orrery sprite
package. It does not install or run sprite-gen, call an image model, inspect a
session, or add a generator dependency to the runtime.

The accepted contract is pinned to [sprite-gen compose_atlas.py at 4f5ccd55](https://github.com/aldegad/sprite-gen/blob/4f5ccd55c7cf06685a41f954acc1e476b7772ece/sprite_gen/compose/compose_atlas.py).
Use a non-degraded `component-row` manifest with matching `frame_layout.rows` and
`animation.rows`, contiguous unique row numbers, explicit positive integer
`durations_ms`, and a boolean `loop`. Legacy fps-only manifests are rejected.
The adapter uses the duration array, not `fps`, and keeps the rectangle sequence
including repeated/shared atlas cells. Row names become clip names. `loop:false`
becomes a once clip holding its final frame after completion.

## Create and apply

```sh
cargo build --locked --release -p orr_package --features sprite-authoring --bin orr_pkg
./target/release/orr_pkg create-sprite \
  --sprite-gen /trusted/export/manifest.json \
  --png /trusted/export/sprite-sheet-alpha.png \
  --license /trusted/export/LICENSE.txt \
  --name my-sprites --version 1.0.0 --out /trusted/packages/my-sprites
./target/release/orr_pkg install /trusted/game --path /trusted/packages/my-sprites
```

The output parent and game project must exist. Use a new package directory.
`--sprite-gen`, `--json`, and explicit `--atlas-size` authoring are mutually
exclusive. The materialized image and supplied license are copied byte for byte,
not re-encoded. The package uses `atlas.png`, `sprites.json`, `LICENSE.txt`, and
`orr.package.json`; upstream paths are inert metadata and never opened.

Bind a scene entity to the installed package in its normal sprite sidecar:

```json
{"package":"my-sprites","document":"sprites.json","source":{"Clip":"idle"},"units_per_pixel":0.5}
```

Existing Collect, Arena, and editor sprite consumers need no new manifest parser.
For a Collect project with its descriptor pointing to the sidecar, build/run the
existing `collect_dodge` player with `--features collect-sprites` and `--project`.
Check `--help` for the project's normal player controls.

## Acceptance and limits

The materialized fixture under `crates/orr_sample/tests/fixtures/sprite-gen` is
original handcrafted test data, **not an image generated by sprite-gen**. Tests
exercise the actual CLI, package installation/reopen, original source removal,
Collect presentation snapshots, millisecond frame boundaries, loop/once, seek,
collection hiding, restart and unchanged paired simulation checksums. PNG alpha
0/64/128/255 survives decoding exactly. These are CPU/playback contracts, not
real-window, GPU pixel, physical-device, or artistic-quality acceptance.

Run the focused gate with `bash tools/check-sprite-gen-import.sh`. It explicitly
executes the otherwise ignored actual-binary test and retains logs outside git.

Existing authoring checks remain: bounded regular files, no symlink ancestry,
4 MiB manifest, 16 MiB PNG/RGBA, 2048-pixel atlas dimensions, 256 clips, 4096
frames per clip, 16384 total frames, and 4096 unique rectangles. Malformed inputs
fail before output creation. Trusted directories must remain stable throughout
use. Publication is visible-partial, not crash-atomic; after a write failure,
inspect the partial directory rather than retrying or deleting it blindly.
The supplied license is preserved, not verified as evidence of rights.
