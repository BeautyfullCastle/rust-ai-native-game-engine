# Viewport mesh vertex editing

The optional `mesh-navigation` editor workflow lets an author select a canonical mesh vertex in the production viewport and drag it horizontally in the XZ plane. `Edit mesh vertices in viewport` arms the tool, and the `Vertex grid snap` text field quantizes horizontal coordinates (for example, `0.25` units); the vertex's current Y value is preserved. The displayed `VERTEX DRAG PREVIEW · host unchanged` is transient local presentation, not a committed scene edit.

Pressing Escape or `Cancel vertex drag` cancels the active gesture and restores its prior preview. Releasing the pointer records one local geometry-history state but leaves the tool armed; finish with `Finish vertex editing` before using local geometry Undo/Redo or placing the agent. `Undo staged geometry` and `Redo staged geometry` remain separate from ERP Undo/Redo. The host Frame remains unchanged until `Place mesh agent` validates and commits geometry together with the agent in one ERP history entry. A staged edit remains unsaved until that placement and a normal scene save.

The tool edits XZ only. Vertex Y remains available through the existing indexed form; malformed or invalid geometry is rejected by the same graph validator. Camera projection and pointer events are exercised through the editor test harness, not physical operating-system input. The graph is embedded in the scene. This workflow does not create colliders or physics, and its optional bare mesh export does not demonstrate native runtime execution.

The ignored Windows x64 hardware-Vulkan acceptance is `mesh_geometry_vertex_ui::viewport_vertex_drag_is_transient_cancelable_snapped_and_persisted`. It requires `ORR_MESH_VERTEX_VIEW_ACCEPTANCE=1`, `ORR_REQUIRE_GPU=1`, `WGPU_BACKEND=vulkan`, and a fresh absolute `ORR_MESH_VERTEX_VIEW_CAPTURE_DIR`. `ORR_MESH_VERTEX_VIEW_OUTPUT` may select an absent scene path. Optional bundle export requires both `ORR_MESH_VERTEX_VIEW_EXPORT_OUTPUT` and `ORR_MESH_EXPORT_RUNTIME`.
