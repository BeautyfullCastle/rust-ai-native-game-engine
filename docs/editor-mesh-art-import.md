# Importing raw agent art

The MeshNavigation editor can turn a local, self-contained static GLB and a license text file into a new package source folder, then embed the resulting model as cosmetic agent art. This workflow starts from the normal local Physics editor: enable the optional `mesh-navigation` feature, choose **File → New mesh scene…**, create and save a mesh graph with an agent, then use the separate **Import raw agent art** and **Mesh agent art** panels to import, apply, and save the model.

The **Import raw agent art** panel asks for **Raw agent GLB**, **Raw agent license**, **New agent package directory**, **Agent package name**, and **Agent package version**. The input directory needs only the GLB and license; do not prepare a package manifest. Review **I have reviewed rights to import this agent art** for each import, then select **Import agent GLB**. Import creates a new static `models` package source with `model.glb`, `LICENSE.txt`, and a generated `orr.package.json`. It does not install or activate that package, change the scene, apply the art, or save a sidecar automatically.

After a successful import, inspect the candidate and use **Apply agent art** to preview it on the navigation agent. **Undo agent art** and **Redo agent art** manage the in-memory art history; **Save agent art** explicitly writes the scene-adjacent `<scene filename>.mesh-art.json` sidecar. The mesh scene itself and navigation physics remain unchanged. Keep the generated package source if you want to inspect or reuse it, but the saved sidecar embeds a validated cooked-model snapshot and license text, so it can reopen and render when both the raw-input directory and generated package source are unavailable. The package is not a current installed dependency.

The import path accepts static, self-contained GLB content only. External resources and scripts are unsupported; importing does not execute package scripts, install dependencies, contact a network, or determine whether the supplied license grants rights. Treat source and output directories as trusted local data. Hashes provide integrity/provenance checks, not publisher authentication or legal verification; path-based checks also do not provide capability-safe or linearizable protection against hostile concurrent filesystem replacement.

For an optional Windows game bundle, enable `mesh-export` as well and use **File → Export mesh game…** after saving the art. The editor validates and copies a separately built local Mesh Player executable; it does not execute it. See [Standalone Mesh Player](editor-mesh-export.md) for bundle and runtime limits. The static navigation graph uses a point agent; cosmetic mesh art does not add character physics or collision.

The opt-in Windows x64 GPU integration acceptance uses `WGPU_BACKEND=vulkan`, `ORR_REQUIRE_GPU=1`, and `ORR_MESH_ART_IMPORT_ACCEPTANCE=1`, with fresh absolute paths supplied through `ORR_MESH_ART_IMPORT_OUTPUT`, `ORR_MESH_ART_IMPORT_CAPTURE_DIR`, `ORR_MESH_ART_IMPORT_PACKAGE_OUTPUT`, `ORR_MESH_ART_IMPORT_EXPORT_OUTPUT`, and `ORR_MESH_EXPORT_RUNTIME`. The test drives the production widgets, checks save/reopen while the source directories are hidden, advances the mesh agent in the actual host, and inspects the same-session exported bundle. It does not claim physical OS input or execute the exported player.
