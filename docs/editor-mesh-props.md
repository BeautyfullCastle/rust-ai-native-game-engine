# Static mesh props

Build the editor with `cargo run -p orr_editor --features mesh-navigation` to enable the optional MeshNavigation workflow. It supports up to 128 static cosmetic props with at most six distinct admitted appearances per mesh scene. Copies share immutable render models after saving and reopening; the existing viewport asset, draw, and memory limits remain. Props are not ECS entities, do not add colliders, and do not alter graph connectivity, agent movement, or navigation physics.

Open **Mesh props** in the MeshNavigation editor. Enter a package source directory and the declared model and license asset paths, acknowledge rights to use the asset, then choose **Load prop candidate**. Loading only validates a static model package; it does not place or save anything. Set the prop name, world-space position, and scale, then choose **Add prop**. Select an existing prop to edit it with **Update selected prop**, or explicitly confirm and remove it with **Remove selected prop**. **Undo prop edit** and **Redo prop edit** operate on bounded in-memory history. Choose **Save props** to persist changes, or **Reload props** to discard no changes and reread the saved data when the document is clean.

Saved props live in a scene-adjacent `<scene filename>.mesh-props.json` sidecar. The sidecar embeds validated cooked static-model data and ties it to the exact scene filename and admitted navigation graph revision. Consequently, reopening requires the same scene and graph revision but does not require the original package source directory. A graph-revision change invalidates the props sidecar rather than silently relocating it. A clean local scene with an invalid sidecar can use **Reload props** after external repair, or explicitly check **I confirm discarding invalid mesh props** and choose **Discard invalid props sidecar**. Discard is enabled only for the matching editable scene when the sidecar digest was observed and the document is clean; it uses that digest as an optimistic guard. Scene Save As retains props in memory and requires an explicit save to create the sidecar for the new filename.

Package source files are inspected locally; this workflow does not install packages, resolve dependencies, execute scripts, or access a network. A license file is provenance metadata, not a legal determination. Hashes detect changes and support integrity checks, not publisher authentication. Use trusted, stable local paths: path-based checks and optimistic digest comparisons do not provide isolation or linearizable protection against hostile or concurrent filesystem replacement. Prop transforms are presentation-only and do not guarantee that art fits the mesh surface or avoids gameplay hazards.

The optional `mesh-export` MeshNavigation standalone Windows bundle includes an admitted props sidecar when one exists. A bundle contains the scene, runtime, manifest, and whichever supported art, props, animation, camera, lighting, and HUD sidecars are saved. Bundle verification checks inventory, byte counts, digests, scene identity, and graph revision before the player opens it. When props are present, export requires a player that advertises the dedicated `.orrprop` `ORR_MESH_PROPS_V1` capability section. More than six props additionally require `.orrdns` `ORR_MESH_DENSE_PROPS_V1`; an incompatible player is refused before publication. Existing appearance capabilities still apply, and export does not execute the selected runtime. Older bundles without props remain supported. This is not package installation or publisher authentication; the sidecar embeds the validated cooked model so the original package source is not needed to reopen or play the scene.

The **Mesh props** panel can also use a locally generated static model package, including one produced by the raw-GLB import workflow. A candidate is not placed until **Add prop** or **Update selected prop** is chosen. Props have bounded undo/redo history; **Remove selected prop** requires explicit confirmation. Unsaved changes block Play. **Save props** writes the separate sidecar, while **Reload props** rereads it only when the document is clean. If a sidecar is invalid, the editor blocks presentation and Play until the file is repaired and reloaded, or the user confirms **Discard invalid mesh props**. Discard uses the previously observed digest as an optimistic guard.

Use [reusable prop assets](editor-mesh-prop-prefabs.md) to capture and explicitly load an applied prop into another admitted mesh graph. Use [prop level grids](editor-mesh-prop-grids.md) to stamp a selected prop with fresh IDs and names as one undoable edit. The 16 MiB sidecar limit and 3584 prop primitive-instance draw limit still apply; this is bounded level dressing, not unlimited asset streaming.

This feature does not claim full character physics, collision, or exhaustive validation of cosmetic presentation.
