# Make a static prop from an animation pose

In Model import, select Cooked animated model and Animated source mode, supply a separate .animated.json file and enable static pose baking. Inspect the source and explicitly choose a clip index; names are advisory and may repeat. Enter sample time in seconds and a new .pose.json identity, then the package/license/destination fields and rights acknowledgement. Bake creates model.orrmodel as a Static package requiring models only. The source remains Animated. Install the result and assign it to a static prop, then Save and reopen. Preview the static package through the existing package browser after import.

Time must be finite and nonnegative. It is checked as f64 against the selected clip duration before f32 narrowing, so a value just above the endpoint rejects even if rounding would land on it. Positive values narrowing to zero reject; negative zero samples zero. The exact final key is sampled without loop wrapping. Shorter tracks use their existing endpoint clamps, and missing tracks keep rest values.

The whole animated source is admitted before sampling, including unused clips and skin data. The existing weighted deformation path includes non-joint ancestors, inverse bind matrices and inverse-transpose normals; the skinned mesh-node transform is not applied twice. Output positions/normals are baked into model space and primitive transforms become identity. Entity/world placement is excluded. UV bits, indices/order, material slots/factors/samplers and image bytes remain intact. Identity and exact recipe/direct-input provenance change; historical resources are not resolved.

Singular or mirrored sampled transforms/blends, unsupported source fields or static-position bounds reject before publication. There is no dropped-primitive, normal or rest-pose fallback, and no collider generation. A pose valid as animation may exceed the static local-vertex bound of one million. Existing strict five-field recipe and input/output/path budgets remain. Installed source assets are immutable.

This authoring action requires room-animated-models to read the source; the static result does not require animation capability. Source/hash/consent and complete request snapshots prevent stale results. Focused CPU tests cover weighted and rigid geometry, final-key sampling, static package types, install/binding/history/Save/reopen and Room use. Windows runtime, GPU pixels, native game export, physical play and video remain unverified.
