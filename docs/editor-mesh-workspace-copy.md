# Duplicate a saved mesh workspace

The Windows x64 `mesh-navigation` editor workflow duplicates the currently open, saved MeshNavigation scene into a new directory. `Duplicate mesh workspace…` opens the `Duplicate mesh workspace` window; provide an absent destination in `Mesh workspace destination directory` and choose `Duplicate mesh workspace`. The copied scene keeps its original filename. The destination contains the scene and only the already-present typed `.mesh-art.json`, `.mesh-props.json`, `.mesh-camera.json`, `.mesh-animation.json`, and `.mesh-lighting.json` sidecars, each byte-preserved. Malformed or stale sidecars are refused rather than silently omitted. Existing directories are not replaced.

This operation copies the saved scene-local presentation state, not the source package directories. The art, props, and animation sidecars embed their cooked model data and licenses; the mesh graph is embedded in the scene. Opening the copy with the original package roots hidden exercises that source-free editor path. Package identity in sidecars is historical provenance, not proof of legal rights or an installed package.

The copy workflow requires an idle, local, admitted MeshNavigation workspace with clean saved state and no pending editor presentations or operations. Place a mesh agent and save before duplicating; blank scenes are not offered by this UI. It does not duplicate arbitrary project folders or copy external package inputs. Filesystem publication is limited to the Windows implementation; this documentation does not claim hostile/concurrent-writer isolation or power-loss recovery.

The separate [mesh lighting workflow](editor-mesh-lighting.md) exercises a scene plus saved lighting sidecar through duplication, source-hidden fresh reopen, Play and a four-file export. That case and the four-presentation seven-file case below are distinct acceptance scopes; they do not demonstrate every combination of all five optional sidecars.

The ignored `mesh_workspace_copy_ui::duplicate_mesh_workspace_preserves_all_saved_presentations_source_free` acceptance drives the actual editor UI and hardware Vulkan viewport. It requires `ORR_MESH_WORKSPACE_COPY_ACCEPTANCE=1`, `ORR_REQUIRE_GPU=1`, `WGPU_BACKEND=vulkan`, a fresh absolute `ORR_MESH_WORKSPACE_COPY_CAPTURE_DIR`, and an absent `ORR_MESH_WORKSPACE_COPY_EXPORT_OUTPUT` plus the archived player path `ORR_MESH_EXPORT_RUNTIME`. `ORR_MESH_WORKSPACE_COPY_SCENE` and `ORR_MESH_WORKSPACE_COPY_DESTINATION` may select an absent scene path and destination directory; the scene must remain inside the test-owned source-workspace directory. The workflow authors a flat quad and adjacent ramp through the geometry UI, places and saves the agent, saves four presentation sidecars, duplicates the workspace, then hides the original workspace and both owned package roots before opening the duplicate from a fresh Physics editor. It checks the 16-tick presentation and verifies the resulting seven-file export bundle. It uses egui test input, not physical operating-system input, and does not demonstrate native execution.
