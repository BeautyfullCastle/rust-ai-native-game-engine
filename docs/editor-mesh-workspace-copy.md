# Duplicate a saved mesh workspace

Use [File → Save mesh workspace](editor-mesh-workspace-save.md) to save the scene and all explicitly applied presentation changes before duplicating. Existing Save / Ctrl+S remains scene-only.

The Windows x64 `mesh-navigation` editor workflow duplicates the currently open, saved MeshNavigation scene into a new directory. `Duplicate mesh workspace…` opens the `Duplicate mesh workspace` window; provide an absent destination in `Mesh workspace destination directory` and choose `Duplicate mesh workspace`. The copied scene keeps its original filename. The destination contains the scene and only the already-present typed `.mesh-art.json`, `.mesh-props.json`, `.mesh-camera.json`, `.mesh-animation.json`, `.mesh-lighting.json`, and `.mesh-hud.json` sidecars, each byte-preserved. A present animation sidecar requires an editor build with `mesh-animated-models`; unsupported, malformed, or stale sidecars are refused rather than silently omitted. The MeshMission configuration is embedded in the scene itself; it is not a separate sidecar, so its scene bytes are copied unchanged with the rest of the scene. Existing directories are not replaced.

This operation copies the saved scene-local presentation state, not the source package directories. The art, props, and animation sidecars embed their cooked model data and licenses; the mesh graph and any MeshMission configuration are embedded in the scene. Mission gameplay and its export profile require a build with `mesh-mission`. Opening the copy with the original package roots hidden exercises the source-free editor path. Package identity in sidecars is historical provenance, not proof of legal rights or an installed package.

The copy workflow requires an idle, local, admitted MeshNavigation workspace with clean saved state and no pending editor presentations or operations. Place a mesh agent and save before duplicating; blank scenes are not offered by this UI. It does not duplicate arbitrary project folders or copy external package inputs. Filesystem publication is limited to the Windows implementation; this documentation does not claim hostile/concurrent-writer isolation or power-loss recovery.

The copy operation validates and preserves each present presentation sidecar, including lighting and HUD, while keeping the scene and sidecar bytes unchanged. A scene with all six sidecars can therefore contain the scene plus six sidecars in the duplicate. MeshMission remains scene data, not an additional file. Export separately admits the typed sidecars and mission game profile; the bundle inventory consists of the scene, each present sidecar, the manifest, and the player runtime.

The ignored `mesh_workspace_copy_ui::duplicate_mesh_workspace_preserves_all_saved_presentations_source_free` acceptance exercises six saved presentation sidecars together: art, props, camera, animation, lighting, and HUD. It also preserves an enabled scene-embedded MeshMission while duplicating the workspace, hides the source workspace and both model-package roots for a fresh Physics-editor reopen, plays and replays through mission completion, and optionally exports the nine-file scene-plus-six-sidecars-plus-manifest-plus-runtime bundle.
